## 1. 项目一句话 + 与 A 线的关系

**把自己已交付的 Olist 电商 MySQL 数仓，从"人写 SQL 出报表"升级为"自然语言问数 Agent"**：用户用中文提问 → 系统检索口径与历史 SQL（RAG）→ 生成 SQL → 只读执行并自校验 → 返回数字、表格与结论。

与既有简历的承接：Olist 项目（ETL+SQL+Power BI）讲"我建了数仓、定义了口径"；本项目讲"我让数仓能被直接提问"。两者构成"传统 BI → AI 增强 BI"一条叙事线，嵌入主版项目经历区，不开新故事。

## 2. MVP 范围界定

**含（五件套，09-27 前全部跑通）**：① Vanna+Olist MySQL+云端 API 最小问数闭环；② 自写编排（规划→生成→只读执行→校验，代码可逐行讲）；③ 自纠错 1 轮（报错回填→重写→复跑，有日志）；④ 30 题评估集（pytest，执行准确率）；⑤ README+架构图+git 仓库。

**不含（对齐清单 3.2，无异议）**：多 Agent 流水线、MCP、Docker Compose、Dify 部署、OpenManus 阅读、Streamlit 美化、评估集超 30 题。W3–W4 加法按清单 3.2 优先级执行。

## 7. 评估集设计

- **题量**：30 题（W3 扩 50）。**题型分布**：单表聚合 8 / 多表关联 10 / 时序环比 6 / 排名对比 6——全部映射到 BI 问数真实场景（"黑五 GMV 环比""复购率""TOP 品类"）。
- **准确率口径**：执行结果比对——同一连接分别执行标准 SQL 与生成 SQL，结果集做行级规范化（排序无关化、数值取整容差）后比对。**分母 = 30；分子 = 执行成功且结果一致的题数**；SQL 文本相似度不参与判定。
- **产出**：`eval/report.md`：总准确率 + 分类别准确率 + 失败题归因（生成错误/执行失败/口径不符）。
